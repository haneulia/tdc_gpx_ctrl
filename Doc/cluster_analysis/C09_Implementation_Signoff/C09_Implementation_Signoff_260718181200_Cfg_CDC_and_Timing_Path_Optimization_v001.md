# C09 Configuration CDC and Timing-Path Optimization Closure v001

## 1. Decision

**The packed configuration CDC, payload write pipeline, and stop-event
ownership stage are ACCEPTED as the internal RTL baseline.**

**The circular line-packer queue experiment is REJECTED. The original static
shift queue is retained.**

**C03 and C06 functional sign-off: PASS.**

**128-bit, AXIS 200 MHz, TDC 200 MHz internal OOC implementation: PASS for
DEDICATED_2X2 and SHARED_DUAL_EDGE.**

**Parent FPGA, clock-tree, pin, bitstream, and board sign-off: OPEN.**

The dedicated route meets setup by only +0.002 ns. This is a valid OOC hard
gate pass, but it is not an implementation guardband. Until the parent design
closes with its actual clock buffers and placement, 200 MHz remains a stress
corner rather than the recommended default operating point. AXIS frequencies
at or below 150 MHz provide a substantially longer period and are the
conservative operating choice.

## 3. Accepted structural changes

### 3.1 One coherent configuration image CDC

The chip CSR path previously instantiated sixteen independent 32-bit
handshake synchronizers. The replacement packs the sixteen words into one
512-bit configuration image and transfers it with one XPM handshake.

The image request is generated from accepted AXI write activity. It is not
generated by a continuously active 512-bit equality comparator. A pending
request is retained while the XPM source acknowledgement is low, so multiple
writes cannot silently lose the latest image.

The resulting contract is:

```text
AXI write accepted
    -> coherent 16-word source image captured
    -> one handshake request retained until accepted
    -> complete image installed together in the AXIS domain
```

This removes fifteen handshake control structures without adding a CSR,
software-visible field, or cross-domain partial-update state.

### 3.2 Registered payload RAM write ownership

The cell builder now registers the selected payload bank, buffer/stop address,
and 17-bit hit data before the distributed-RAM write. The stage has one-cycle
latency and initiation interval one, so consecutive accepted hits remain
supported.

The stage removes input decode, count selection, and bank selection from the
RAM write-enable cone. Visible `max_hits` count/drop behavior and the physical
seven-bank storage contract are unchanged.

### 3.3 Registered stop-event ownership

The stop decoder now captures an owned raw event in a one-cycle stage. Expected
stop decode and monotonic runtime-state update are performed in one owner
process instead of duplicated arithmetic/control cones.

The stage preserves:

- one accepted stop event per clock
- ordered event output
- expected-count accounting
- final-beat alignment immediately after the last staged stop event
- existing CSR and AXIS contracts

### 3.4 Static line-packer queue retained

The original line packer uses a small statically indexed word array. Output
consumption shifts the remaining words toward index zero. Although this looks
less elegant in source code than a circular queue, Vivado can optimize its
constant indexes effectively for the supported 32/64/128-bit widths.

The six direct line-packer tests added during the queue experiment are retained:

- width 32/64/128 with `max_hits = 7`
- width 32/64/128 with `max_hits = 3`

## 7. Rejected experiments

### 7.1 Continuously compared packed CSR image

The first packed-image implementation used a continuously active 512-bit
source-image comparison. Dedicated implementation passed, but the shared route
failed at WNS -0.031 ns with 49 failing endpoints. The comparator-trigger
scheme was replaced by the accepted AXI-write event trigger.

An intermediate event-triggered shared implementation terminated during
physical optimization and was not used as evidence. The final combined shared
route completes and passes at +0.087 ns.

### 7.2 Circular line-packer queue

The pointer-based circular queue passed the expanded C06 regression, but
dynamic word indexing inferred large mux structures.

| Metric | Static shift queue | Circular queue | Circular delta |
|---|---:|---:|---:|
| Synth LUT | 21,349 | 21,829 | +480 |
| Synth FF | 31,653 | 31,857 | +204 |
| Control sets | 919 | 925 | +6 |
| Dedicated WNS | +0.002 ns | +0.004 ns | +0.002 ns |

The 2 ps setup improvement does not justify the resource and verification
cost. Commit `b84c0ba` restores the static queue while keeping the expanded
tests.

## 8. CDC, constraints, and DRC boundary

The final implementation uses explicit asynchronous clock groups for AXI,
AXIS, and TDC clocks. The packed configuration image uses one XPM handshake,
and no independent word can become visible ahead of the rest of the image.

The remaining implementation warnings are expected at OOC scope:

- `NSTD-1`: top-level I/O standard belongs to the parent design
- `UCIO-1`: top-level pin location belongs to the parent design
- `HD.CLK_SRC`: actual parent clock-buffer locations are unavailable OOC
- PS7 and board connectivity checks cannot close inside this block

No warning severity was demoted. These warnings prevent an OOC timing pass from
being treated as bitstream or board sign-off.

## 9. Clock and operating guidance

The supported clock set remains 50/100/125/150/200 MHz. The HDL generics must
match the physical clocks because timeout and processing-budget calculations
depend on them.

Signal-processing timing limits should be expressed in the AXIS domain when
that domain performs the bounded work. The architecture assumes the AXIS
processing clock is not faster than the available TDC-side production rate;
system-level margins must still be checked against the slower effective
pipeline stage.

Recommended release policy:

1. Use AXIS 150 MHz or lower as the guardbanded default until parent timing is
   available.
2. Keep 200/200 MHz as the mandatory OOC stress sentinel for every later RTL
   change.
3. Enable 200 MHz in a product build only after parent placement, real clock
   insertion, I/O constraints, and bitstream DRC all pass.

## 11. Next optimization direction

Do not replace the line-packer word array with another generic dynamically
indexed queue. The experiment shows that source-level elegance does not map to
better 7-series hardware in this case.

The next reasonable options are, in order:

1. Run the final RTL in the parent design and capture actual clock insertion
   and placement before another architecture change.
2. If 200 MHz parent timing fails, first test physical placement guidance or
   local register replication for the dedicated line-packer control path.
3. Only if RTL must change, evaluate compile-time width-specialized static
   packers for 32/64/128 bits. Each candidate must retain the six direct packer
   tests and both 200 MHz route sentinels.
4. Avoid new runtime counters, pointers, or arithmetic unless they remove a
   measured path and improve routed timing materially.

## 12. Final status

The configuration CDC and local timing-path optimization round is closed for
the internal RTL baseline. Functional contracts are intact, control sets and
logic are reduced, both 200 MHz OOC routes meet setup and hold, and the failed
circular-queue direction has been removed from the final code.

The dedicated +0.002 ns result is too small for unconditional product sign-off.
The next high-value work is parent-level implementation evidence, not another
unmeasured increase in RTL state.
