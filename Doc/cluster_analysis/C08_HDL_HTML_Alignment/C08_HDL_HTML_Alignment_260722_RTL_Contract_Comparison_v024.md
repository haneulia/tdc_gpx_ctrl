# C08 HDL/HTML Alignment: RTL Contract Comparison

- Date: 2026-07-22
- Stage: S19 / integration result import
- Product reference: AXIS 150 MHz, TDC 200 MHz, output 32 bit
- Verdict: **PASS for the executable RTL-to-HTML contract; implementation sign-off remains separate**

## 1. Purpose

Stage S19 turns the C08 HTML from a manually aligned calculator into a local
result checker. It accepts either the compact `rtl_contract.json` or the full
`rtl_result.json`, optionally applies the scenario to the HTML controls, and
then compares observed RTL values against the recalculated HTML model in time
and ownership order.

No network request is used. The selected JSON remains local to the browser.

## 2. Ambiguous topology issue found

The earlier contract exposed `chip_slope_mask`, but that field is the slope bit
generated by each behavioral GPX chip. It describes test stimulus, not the
elaborated `tdc_gpx_top` capability masks. Inferring build topology from that
single field could make the HTML report a false match, especially for
same-chip dual-edge or a future sparse build.

The integration TB now maps its build profile explicitly into `tdc_gpx_top`
and reports both ownership layers:

| Ownership layer | Contract fields | Meaning |
|---|---|---|
| Build-time | `present_chip_mask`, `rise_capability_mask`, `fall_capability_mask` | Elaborated physical/logical capability |
| Runtime | `active_chip_mask`, `runtime_rise_chip_mask`, `runtime_fall_chip_mask` | CTL21 and active-mask result for this run |
| Stimulus only | `chip_slope_mask` | Slope bit emitted by the behavioral GPX model |

The HTML can display an older inferred contract for diagnosis, but inferred
build/runtime masks cannot produce PASS. This makes the evidence requirement
explicit instead of silently trusting a convenient derivation.

## 3. Comparison sequence

The panel checks 26 rows in this order:

1. schema and RTL verdict;
2. AXIS/TDC clocks and output width;
3. 5 ns range CSR and both domain conversions;
4. scan timeout, max hits, falling enable, and stops;
5. build, active, and runtime slope masks;
6. columns, faces, HSIZE rise/fall, and VSIZE;
7. completed-line beat accounting;
8. Laser start/stop/result closure and slope TLAST closure;
9. `STAT5`, `STAT6`, `STAT7`, and zero fault counters.

Any failed row forces both the contract badge and the top Frame-rate verdict to
CHECK. Optical or Ethernet margin can no longer leave the top status green
while an imported RTL contract is inconsistent.

## 5. Efficiency and policy decisions

The importer reuses the HTML's existing `calc()` geometry rather than adding a
second packet calculator. This avoids duplicate HSIZE/clock arithmetic. The
contract normalizer handles compact and full result files through one path,
and the comparison function is pure enough to run as a browser self-test.

`max_scan_5ns_ticks=0` remains intentional for this smoke. Choosing a nonzero
assembler timeout requires an explicit range plus GPX drain plus AXIS service
budget; it should not be synthesized from optical range alone.

1. an independent AXI 100 MHz dynamic simulation;

4. the new xc7z020clg484-2 parent implementation, XDC, timing, and CDC reports;
5. board-level electrical and optical validation.

Optimization should proceed only inside behavior already covered by these
contracts, with each simplification rerunning the explicit JSON comparison.
