## 1. C03 시작 선언

C03는 `tdc_gpx_top.vhd`의 Cluster 3 주석 기준으로 `cell_pipe`를 분석 대상으로 한다.

`tdc_gpx_top.vhd`의 파이프라인 주석은 다음 구조를 제시한다.

| Cluster | RTL 주석 기준 | C03 관계 |
|---|---|---|
| C02 | `decode_pipe`: `decoder_i_mode + raw_event_builder + skids` | C03 입력 event stream 생성 |
| C03 | `cell_pipe`: slope demux + `cell_builder` x8 | 이번 분석 대상 |
| C04 | `output_stage`: face assembler + sync FIFO + header | C03 출력 소비자 |

## 2. 분석 대상

### 2.1 중심 RTL

| 파일 | 역할 | 1차 확인 포인트 |
|---|---|---|
| `tdc_gpx_cell_pipe.vhd` | C03 wrapper, slope demux, rising/falling cell_builder x8 연결 | registered ready, drain_done fanout, per-slope abort, tuser 전달 |
| `tdc_gpx_cell_builder.vhd` | sparse event를 dense cell slice로 변환 | dual buffer ownership, shot_start, IFIFO1/IFIFO2 split output, timeout/drop/fault |
| `tdc_gpx_pkg.vhd` | cell format/helper | 16-bit slot, runtime beat 공식, 32/64/128 지원 |

### 2.2 경계 RTL

| 파일 | 역할 | 분석 목적 |
|---|---|---|
| `tdc_gpx_decode_pipe.vhd` | C02 event stream producer | event AXIS/tuser 계약 확인 |
| `tdc_gpx_output_stage.vhd` | C04 cell stream consumer | C03 output tdata/tlast/tuser가 다음 단계에 맞는지 확인 |
| `tdc_gpx_top.vhd` | Cluster 연결 | `s_cfg_face_r.max_hits_cfg`, `shot_start`, abort, status 연결 추적 |

## 3. 절대 기준과 운용 전제

| 항목 | C03 기준 |
|---|---|
| Datasheet 기준 | TDC-GPX I-Mode single raw hit 의미와 FIFO read 결과 해석은 Datasheet를 우선한다. |
| 운용 mode | I-Mode single만 포함한다. Quiet/M-mode/Continuous는 제외한다. |
| Clock | 기존 C02 기준과 동일하게 200 MHz 분석을 기본으로 한다. |
| Output width | 32/64/128-bit만 포함한다. 256-bit는 반영하지 않는다. |
| Cell slot | 현재 RTL은 lower 16-bit hit slot 저장 계약이다. full 17-bit 보존은 finding 후보로 검토한다. |
| Runtime max_hits | `CTL21.max_hits_cfg`는 face `packet_start` 전 설정된 값을 사용한다고 본다. |
| Coding rule | 합성 가능한 VHDL, 순차논리 기본, 조합논리는 최대 2-depth까지만 허용한다. |
| TB AXI4-Lite | TB에서 AXI4-Lite read/write helper는 `px_utility_pkg.vhd` 정의를 사용한다. |

## 4. 분석 절차

1. Datasheet 기준으로 I-Mode raw hit와 stop/channel 의미를 먼저 재확인한다.
2. C02 event AXIS `tdata/tuser` 계약을 C03 입력 표로 재정리한다.
3. `cell_pipe` registered slope demux의 ready/valid 경계를 분석한다.
4. drain_done control beat가 rising/falling 양쪽 cell_builder에 전달되는 타이밍을 확인한다.
5. `cell_builder` dual buffer ownership FSM을 `p_collect`와 `p_output`으로 분리해 분석한다.
6. IFIFO1 early output, IFIFO2 wait, timeout EOS, drop/quarantine 흐름을 timing diagram으로 작성한다.
7. 32/64/128-bit별 `max_hits_cfg`에 따른 cell beat, slice latency, throughput, pipeline, II를 산출한다.
8. C02에서 넘긴 16-bit slot vs 17-bit raw hit 보존 문제를 code review finding으로 판단한다.
9. 필요한 경우 testbench 보완 계획을 세우고, 사용자 승인 후 코드 보완을 진행한다.

| Review | 코드 부실/위험 항목은 severity와 근거 line으로 기록된다. |
| PPT | 핵심 구조, 상태머신 관계도, timing block diagram을 도식으로 포함한다. |
